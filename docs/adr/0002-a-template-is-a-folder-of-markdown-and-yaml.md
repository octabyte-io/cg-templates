# 2. A template is a folder of Markdown and YAML, and JSON is only ever generated

Status: accepted, amended by [ADR-0003](0003-a-folder-holds-cloudgates-template-beside-its-page-and-releases-publish-catalogue-zip.md): the folder also holds
Cloudgate's `template.yaml` and other template files, `template.yaml` owns name, description,
tags and links, and the generated file Cloudgate reads is `catalogue.zip`.

## Context

A template needs both page content (headings, screenshots, FAQ) and deploy settings. Writing
rich content inside JSON is hard, and a single shared `meta.json` turns every contribution into
a merge conflict. The Cloudgate deploy format is also still changing.

## Decision

Each template is `templates/<id>/` holding:

- `index.md`: structured fields in frontmatter, the page in Markdown.
- `cloudgate.yaml`: deploy settings only.
- a logo, and optional screenshots.

Any JSON (the catalogue Cloudgate reads, the search index) is generated by the build. Nobody
edits it by hand.

## Consequences

- Contributors touch only their own folder, so pull requests do not conflict.
- When the Cloudgate format changes, only `cloudgate.yaml` and the one build step that converts
  it change; page content is untouched.
- The folder name is the template id and its URL, so renaming a folder needs a redirect.
